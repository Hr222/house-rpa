# 询价返回改造

> 状态：需求已确认，待实现。

## 1. 本块目标

让请求方能够区分：小区不存在、期数未明确、任务已受理、询价完成以及采集和入库过程中的部分失败。

本块只调整 FastAPI 对外返回和任务结果表达，不改变价格算法。

## 2. 前置返回

### 小区未找到

编排层查询不到小区时，直接返回业务失败结果：

```text
未找到小区
```

该结果不创建 `taskId`，不进入 RPA，不写入 `property_records`。

### 期数未明确

查询返回多个期数时，直接返回候选小区信息，至少包含：

```text
community_group_id
community_id
canonical_name
phase
aliases
city
administrative_district
```

该结果不创建 RPA 任务。请求方明确具体期数后重新提交请求。

### 唯一小区

查询到唯一小区后，创建既有询价任务并返回任务受理信息。`community_id` 不要求请求方提交，由服务端在编排层取得并保存。

## 3. 任务结果

任务受理和任务查询结果应能携带已确认小区摘要：

```text
community_id
canonical_name
phase
aliases
```

任务完成后，在现有询价结果基础上增加入库摘要，至少能表达：

```text
storage_status
listing_upsert_count
deal_upsert_count
skipped_listing_count
skipped_deal_count
storage_error_count
```

询价结果成功与入库结果需要独立表达：RPA 采集成功但部分入库失败时，不能把整个询价结果错误标记为平台采集失败；同时必须保留入库失败信息，供归档重入库。

回调结果与任务查询结果保持相同的小区摘要和入库摘要语义。

## 4. 重点验收

- 未知小区返回明确业务结果，不产生任务。
- 多期小区返回候选信息，不自动选择。
- 唯一小区返回既有受理结果，并能在任务结果中看到小区摘要。
- 任务完成后能区分询价结果和房源入库结果。
- 入库部分失败时，响应中保留错误摘要，不覆盖已经成功的询价结果。
