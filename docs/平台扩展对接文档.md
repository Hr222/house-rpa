# 平台扩展对接文档

> 本文说明如何把一个新的采集平台接入 jeethink-rpa。
> 工程已重构为「URL 白名单直达」形态：**RPA 层只负责抓取**，任务编排、小区身份、
> 估价与数据沉淀分别在 `app/inquiry/`、`app/algorithm/`、`app/property_records/`。
> 新平台的全部专属逻辑只允许出现在自己的平台目录内。

## 1. 平台概念

本项目里「一个平台」是一个**自包含的聚合目录**，而不是散落在各层的若干文件：

```text
app/rpa/platforms/<code>/
├─ shell.py      # 平台薄壳适配器（继承 base.PlatformAdapter，唯一对外入口）
├─ collector.py  # 采集适配逻辑（URL 直达、翻页、风控、组装 PlatformResult）
├─ parser.py     # 纯函数解析器（HTML/接口响应 → 结构化数据，可独立单测）
└─ constants.py  # 平台固有常量（START_URL 等）
```

一个平台要生效，除四文件外还需要三处登记：

1. `app/rpa/platforms/<code>/__init__.py` 导出薄壳类；
2. `app/rpa/platforms/city_map.py` 登记城市能力（支持的城市与 URL 模板）；
3. `app/rpa/registry.py` 的 `build_default_adapters()` 加入实例。

边界规则：

- 平台间共性（风控协议、归属校验、结果组装）一律放 `base.py`，
  **禁止复制进平台目录**；旧搜索式链路的遗留工具（点击/停留/空页检测，
  base.py 内已标注【遗留】/【回退】）同样留在 base，**新平台禁止使用**；
- 平台专属规则（验证码/登录 marker、选择器、URL 结构）只允许出现在平台目录内，
  **禁止为了复用而上提**到公共层；
- `parser.py` 保持纯函数：html 进、数据出，禁止 IO 与浏览器操作；
- `collector.py` 不直写业务数据库，浏览器生命周期归 Runtime。

当前已接入 5 个网页平台：贝壳(ke)、安居客(ajk)、链家(lj)、房天下(fang)、乐有家(lyj)。

## 2. 平台目录四文件

### `constants.py`

平台固有常量。`START_URL` 必填（`open_session` 初始打开与保活刷新用；采集时目标
城市 URL 由 `city_map.get_start_url(code, city)` 动态获取）。平台专属阈值也放这里，
如 fang 的 `FANG_SOFT_BLOCK_SECONDS = 45.0`（软风控判定阈值）。

### `parser.py`（纯函数）

html 进、数据出，无 async、无 page 依赖，可独立单测（`tests/parsers/test_<code>.py`）。
按需实现：

| 函数 | 用途 |
|---|---|
| `parse_listing_snapshots(html, base_url=None) -> list[ListingSnapshot]` | 在售快照（`base_url` 用于把相对详情链接 urljoin 成绝对 `listing_url`） |
| `parse_deal_records(html) -> list[tuple]` | 成交明细（area, date, total_price万, price 元/㎡） |
| `parse_community_avg_price(html) -> float \| None` | 平台卡片/详情页的小区参考均价（仅溯源，算法不用） |
| `parse_total_pages(html) -> int` | 声明的总页数（分页兜底用） |

解析函数公开名不带 `_` 前缀，内部辅助带 `_`。**选择器与 marker 必须基于真实页面
dump 校准**（`--debug` 导出），禁止盲写。

### `collector.py`（采集适配逻辑）

模块级函数形态，被 shell 委托。标准函数集：

| 函数 | 职责 |
|---|---|
| `collect_listing_by_url(page, *, community_name, listing_page_url, deal_page_url=None, request_id=None, max_pages=50) -> PlatformResult` | 采集主入口：直达挂牌页 → 风控 → 空态 → 归属 → URL 翻页 →（可选）成交页 |
| `detect_block(url, html) -> tuple[bool, str]` | 平台专属风控/登录检测（验证码 marker、登录 URL/HTML、软失效特征） |
| `is_no_result(html) -> bool` | 空态判定（命中即 NO_DATA，空态页下方的推荐位不解析） |
| `reset_to_start_page(page, city="深圳") -> page` | 采集结束复位回本城市首页 |
| `probe_ready(main_page) -> tuple[bool, str]` | 轻量就绪探测（页面可用且未风控即 READY） |

`collect_listing_by_url` 内部职责与顺序（参照 `fang/collector.py`，各平台同构）：

1. `page.get(listing_page_url)` 直达挂牌页（URL 来自编排层下发的白名单）；
2. `wait_and_reload_after_block(page, detect_block, label)` 走统一风控协议；
3. `is_no_result(html)` 空态短路；
4. `parse_listing_snapshots` 解析 + `has_matching_community_snapshots` 归属校验
   （不符则整页弃用）；
5. `_build_pagination_urls` 由第 1 页 HTML 提取后续页 URL 直达翻页
   （只收录携带同一小区 token 的链接）；
6. `deal_page_url` 存在时独立直达成交页采集全量真实成交；
7. 组装 `PlatformResult`：**只回传原始明细**（`listing_snapshots` + `deal_records`），
   `quote_prices/deal_prices` 置空镜像（兼容字段），面积收敛与估价由算法层接管。

平台专属增强规则（按需）：如 fang 的软风控（`FangSoftBlockError` +
`check_soft_block_elapsed`，内容超过 `FANG_SOFT_BLOCK_SECONDS` 未渲染 → 会话恢复
一次 → 仍超时按 ERROR 返回）。

### `shell.py`（薄壳适配器）

继承 `PlatformAdapter`，是 runtime/service/registry 唯一接触的平台对象。标准结构
（完整示例见 `ke/shell.py`）：

```python
class XPlatformAdapter(PlatformAdapter):
    code = "x"
    name = "某某平台"
    start_url = START_URL

    async def open_session(self, browser, new_tab=False) -> PlatformSession:
        page = await browser.get(self.start_url, new_tab=new_tab)
        await page
        return PlatformSession(code=self.code, name=self.name,
                               start_url=self.start_url, page=page, ready=True)

    async def collect(self, browser, session, request) -> PlatformResult:
        skip = self.check_city_support(request.city, request.request_id)
        if skip is not None:
            ...  # 保活刷新 + 返回 NO_DATA
        await self.ensure_city_navigated(session, request.city)

        # URL 白名单直达：编排层未下发入口 → 直接 NO_DATA，不做任何搜索交互
        listing_url = (request.platform_listing_pages or {}).get(self.code)
        if not listing_url:
            return PlatformResult(name=self.name, status=PlatformResultStatus.NO_DATA,
                                  reason="无挂牌入口（community_platform_pages 未初始化）",
                                  request_id=request.request_id)
        deal_url = (request.platform_deal_pages or {}).get(self.code)

        result = await x_adapter.collect_listing_by_url(
            page=session.page, community_name=request.community_name,
            listing_page_url=listing_url, deal_page_url=deal_url,
            request_id=request.request_id, city=request.city,
        )
        session.page = await x_adapter.reset_to_start_page(session.page, request.city)
        return result

    async def _probe_ready(self, page, html) -> tuple[bool, str]:
        return await x_adapter.probe_ready(page)

    def detect_block(self, url, html):
        return x_adapter.detect_block(url, html)

    def is_no_result(self, html): ...
    def parse_listing_snapshots(self, html, base_url=None): ...
```

## 3. 必须复用的工程公共件

以下能力全部在 `base.py`（或指定模块）实现，**直接导入使用，禁止在平台目录复刻**：

| 函数/机制 | 用途 |
|---|---|
| `detect_block_with_common(detect_func, url, html)` | 平台专属 `detect_block` 优先，未命中叠加公共 URL/HTML 验证码兜底 |
| `is_generic_captcha_page(html)` | 通用验证码页兜底（正文含验证码话术且无业务特征） |
| `wait_and_reload_after_block(tab, detect_func, label)` | **风控统一处理入口**：检测 → 等人工回车 → 重取，循环到恢复；所有页面跳转后调用 |
| `wait_for_manual_unblock()` | 人工回车协调器（命中拦截阻塞等人工回车） |
| `community_name_match(request_name, captured_name)` | 结构化小区名匹配（期数/噪声规则内建） |
| `has_matching_community_snapshots(snapshots, name)` | 解析后首轮归属校验 |
| `filter_snapshots_by_community(snapshots, name)` | 逐页/返回前防御过滤 |
| `prepare_listing_data(snapshots, community_name)` | 归属过滤 + 同源 `quote_prices` 镜像 |
| `short_circuit_result(name, status, reason, request_id, started_at, ...)` | 统一构造短路返回（NO_DATA 等），自带 `elapsed_seconds` |
| `safe_select_and_click(page, selector, ...)` | 【回退】安全选择+点击：找不到 → dump → 风控检测 → 恢复重试 → 点击；None 即优雅停止（lj 成交翻页兜底） |
| `_human_click(page, element, label)` | 【回退】真人节奏点击（JS 优先、mouse 兜底），仅回退点击路径使用 |
| `human_linger(page, page_no)` | 【遗留】旧搜索式链路的翻页停留，现行链路无调用方 |
| `check_empty_listing_page(...)` | 【遗留】旧搜索式链路的翻页空页检测 |
| `click_area_segment(...)` | 【遗留】旧搜索式链路的面积档位点击，URL 直达形态不再使用 |

**口径红线**：面积筛选（严格 ±1㎡、弱参考 ±20㎡）、跨平台去重、成交的面积/日期
收敛全部在算法层（`app/algorithm/deal_screening.py`、`selection.py`）。RPA 只回传
原始明细，任何平台不得在采侧做面积筛选或调 `app.algorithm` 参与估价。

## 4. 数据契约：入参与出参

### 入参：`InquiryRequest`（编排层构造，平台只读）

| 字段 | 说明 |
|---|---|
| `community_name` | 主数据正式名（非用户输入原文） |
| `city` / `administrative_district` | 城市与行政区（随请求透传） |
| `area` | 请求面积（㎡），RPA 不用它做页面筛选 |
| `request_id` | 客户端请求标识，用于日志和结果关联；内部任务 ID 由 Runtime 单独维护 |
| `platform_listing_pages` | `{code: 挂牌页 URL}` 白名单——**本平台无键 = 未初始化，直接 NO_DATA** |
| `platform_deal_pages` | `{code: 成交页 URL}`（仅 lj/fang 有） |

### 出参：`PlatformResult`

| 字段 | 要求 |
|---|---|
| `name` | 平台中文名（如 "贝壳"，入库层按别名归一） |
| `status` | `SUCCESS` / `NO_DATA` / `NO_MATCHING_AREA` / `WAIT_MANUAL_VERIFY` / `LOGIN_EXPIRED` / `ERROR` |
| `listing_snapshots` | 目标小区在售快照（`ListingSnapshot`，含 `listing_url`）；不得混入无关小区 |
| `deal_records` | 成交原始明细 dict（`{area, date, total_price(万), price(元/㎡)}`），**不做面积/日期筛选** |
| `deal_source` | `"成交记录"`（真实成交）或 `"无"`；禁止再把均价顶替写进成交 |
| `quote_prices` / `deal_prices` | 兼容镜像，URL 直达形态置 `[]` |
| `community_avg_price` | 平台卡片均价，仅溯源，算法不参与 |
| `reason` | 短路原因（NO_DATA/WAIT_MANUAL_VERIFY/LOGIN_EXPIRED 时必填，人工可读） |
| `listing_page_url` / `deal_page_url` | 实际使用的入口 URL（后台落库凭它归属） |
| `request_id` / `elapsed_seconds` / `detail_url` | 常规字段 |

状态语义红线：`ERROR` 只代表本次采集失败，**不得**据此把平台健康状态置为异常；
`WAIT_MANUAL_VERIFY`/`LOGIN_EXPIRED` 由 Runtime 按版本保护规则回写平台健康状态。
禁止把登录失效/验证码误报成 `NO_DATA`。

## 5. PlatformAdapter 接口清单

| 成员 | 谁实现 | 说明 |
|---|---|---|
| `code` / `name` / `start_url` | 子类（类属性） | 平台标识；`start_url` 为默认首页 |
| `requires_login` | 子类可选 | 默认 `True`；无需登录的平台（如 ajk）设 `False` |
| `uses_browser` | 子类可选 | 默认 `True`；无需浏览器的纯接口平台可设 `False`，Runtime 不为其建浏览器 |
| `open_session(browser, new_tab=False)` | **子类必须** | 打开常驻首页，返回 `PlatformSession` |
| `collect(browser, session, request)` | **子类必须** | 按 §2 shell 模板实现（城市检查→白名单直达→委托 collector→复位） |
| `detect_block(url, html)` | **子类必须**（委托 collector） | 平台专属风控检测 |
| `check_ready(session)` | 基类已实现 | body+HTML（含 WebSocket 重试）→ `detect_block_with_common` → 登录检测（正向"退出"+反向登录链接）→ `_probe_ready` |
| `_probe_ready(page, html)` | 子类按需 | 平台特有就绪探测（默认通过；建议委托 collector.probe_ready） |
| `keepalive(session)` | 基类已实现 | 默认复用 `check_ready` |
| `check_city_support` / `ensure_city_navigated` | 基类已实现 | 城市能力与导航，薄壳 `collect()` 开头调用 |
| `is_no_result` / `parse_listing_snapshots` / `parse_community_avg_price` / `parse_deal_records` | 子类按需（能力多态入口） | 无对应能力的平台不重写（调用即 `NotImplementedError` 明示缺失） |

## 6. 风控与人工确认协议

1. 页面跳转后（挂牌页、成交页、每个翻页 URL）**必须**调用
   `wait_and_reload_after_block(page, detect_block, label)`：内部先平台专属
   `detect_block`，未命中叠加公共兜底（URL captcha 标识 + 通用验证码页判定），
   命中则置前标签页、等人工回车、重取，循环到页面恢复——风控 HTML 不得流入解析。
2. 验证码/登录 marker 是各平台自有安全系统的特征，**必须基于真实 dump 校准**
   （`--debug` 导出对照），禁止盲写；登录失效注意两种形态：硬失效（跳登录 URL）
   与软失效（URL 不变、正文出现登录墙，如 fang 的"请输入手机号/扫码登录"，
   贝壳/链家的 `ucid:''` 判据）。
3. 状态区分：人机验证 → `WAIT_MANUAL_VERIFY`；登录失效 → `LOGIN_EXPIRED`
   （Runtime 映射 `WAIT_LOGIN`）。普通空数据/异常不得改变平台健康状态。
4. 平台专属行为规则按需提升为正式机制，如 fang 软风控（内容 45s 未渲染 →
   会话恢复一次 → 仍超时 ERROR，见 `fang/collector.py` 与 `fang/constants.py`）。

## 7. 新平台接入步骤

按以下顺序推进（每步可独立验证，不要跳步）：

1. **登记**：`city_map.py` 加城市能力；建 `platforms/<code>/constants.py`（START_URL）。
2. **MVP 验证页面结构**：写 `scripts/collect_community_data/rpa/<code>_mvp_test.py`
   最小链路（`--listing-url` 直达 → `--debug` dump），校准解析规则与选择器。
   MVP 允许粗糙，目标是拿到"全链路验证通过的实现"。
3. **parser.py**：把验证过的解析逻辑提升为纯函数；配 `tests/parsers/test_<code>.py`
   喂构造 HTML 单测。
4. **collector.py**：`collect_listing_by_url` / `detect_block` / `is_no_result` /
   `reset_to_start_page` / `probe_ready`（全套同构参照 `fang/collector.py`）。
5. **shell.py**：四件委托 + `_probe_ready`（参照 `ke/shell.py`）。
6. **注册**：`platforms/<code>/__init__.py` 导出薄壳类 + `registry.build_default_adapters()`
   加实例。
7. **入口白名单初始化**：跑 `scripts/initialize_community_page/` 流程把目标小区的
   挂牌/成交页 URL 写入 `community_platform_pages`；此后编排层即可向该平台下发比价任务。

## 8. 注册与入口白名单

注册只改两处（runtime/service/api/algorithm 一律不改）：

```python
# app/rpa/platforms/<code>/__init__.py
from app.rpa.platforms.<code>.shell import XPlatformAdapter

# app/rpa/registry.py
from app.rpa.platforms import (..., XPlatformAdapter)

def build_default_adapters() -> list[PlatformAdapter]:
    return [KePlatformAdapter(), ..., XPlatformAdapter()]
```

入口白名单不是代码：目标小区的挂牌/成交页 URL 存在
`property_records.community_platform_pages` 表（`community_id + source_platform` 唯一），
由 `scripts/initialize_community_page/` 流程写入。白名单里没有的小区，该平台直接
`NO_DATA`（reason="无挂牌入口"），这是设计行为而非故障。

## 9. 多城市支持

- 广东 21 地级市；各平台 URL 前缀命名规则不统一（缩写/全拼混用），**必须显式登记**
  在 `city_map.CITY_MAP`，不能用规则推导；
- 新平台接入时同步登记 `CITY_MAP["<code>"]` 与 `_URL_PATTERNS["<code>"]`；
- 前缀来源：平台城市选择页 HTML dump（参考 `city_map.py` 文件头注释与数据来源说明）；
- 采集流程中的城市处理已由基类封装：`check_city_support` → `ensure_city_navigated` →
  collector 内 `reset_to_start_page(page, city)`。

## 10. 调试与验收清单

调试：新平台接入全程开 `--debug`（HTML dump 到 `debug/`）。重点留存：首页、
挂牌页、每个翻页、成交页、登录失效/验证码现场。

验收清单（全部通过才算接入完成）：

- [ ] `--manual-login` 启动后平台能确认 READY（`probe_ready` 判定准确）
- [ ] 白名单内小区 → `SUCCESS` + `listing_snapshots`（含 `listing_url`）
- [ ] 白名单外小区 → `NO_DATA`（reason="无挂牌入口"）
- [ ] 真实空态小区 → `NO_DATA`（`is_no_result` 命中，不误吞推荐位）
- [ ] 归属不符 → 快照整页弃用，不污染数据
- [ ] 多页小区 → URL 直达翻页全量采集；风控命中 → 等人工恢复后续采
- [ ] （lj/fang）成交页全量采集，明细键名 `{area, date, total_price, price}`

## 11. 迭代模式：MVP 先行 → 工程改造 → MVP 依赖

平台扩展采用固定迭代循环：

1. **MVP 先行**：新平台先写 `scripts/collect_community_data/rpa/<code>_mvp_test.py`，
   用最小链路验证页面结构，基于 dump 校准 parser。MVP 允许粗糙。
2. **工程改造**：把验证过的逻辑提升为工程四件（constants → parser → collector →
   shell），补齐风控协议、状态语义与 `PlatformResult` 组装，注册进 registry。
3. **MVP 依赖**：工程件稳定后，**回头删掉 MVP 自己的采集主循环**，改为薄调用工程
   `collect_listing_by_url` 等（参照 `ke_mvp_test.py`）。MVP 保留的价值是页面结构
   变化时的快速核对工具。

> 禁止长期维护"MVP 一套 + 工程一套"的平行实现——工程修复必须同步惠及 MVP，
> 否则 MVP 的验证结论会与工程行为脱节（本项目已多次因此踩坑：lj 成交分页
> token 正则、ke 就绪探测死引用均源于此）。
