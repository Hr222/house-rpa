# 房源记录模块

`app/property_records/` 保存 RPA 从外部平台读取到的成交事实和当前挂牌状态。
它不是估价模块，也不保存本系统的最终取值、估价结果或安居客/乐有家的均价顶替值。

## 数据表

- `deal_records`：链家、房天下的单条成交事实。成交日期、建筑面积、总价和单价均为必填；总价统一保存为元。相同来源下五项事实完全一致时幂等更新，不同来源仍各保存一条。
- `community_platform_pages`：每个 `community_id` 在一个网页平台上的小区页面入口，统一保存挂牌列表页和成交列表页。后续任务可优先直达已有入口；缺失或失效时才回退平台搜索流程。
- `listing_records`：各平台当前挂牌状态。外部唯一键是 `source_platform + listing_url`，重复抓取更新原记录；下架只设置 `is_deleted=1`。
- `listing_record_logs`：挂牌价格有效快照。每次当前挂牌记录成功更新时同步写入，只保存 `listing_record_id`、采集时间、总价和单价，不保存标题、户型、面积或涨幅结果。

`community_platform_pages` 以 `community_id + source_platform` 唯一，保存
`source_community_name`、`listing_page_url` 和 `deal_page_url`。两个页面 URL 可以只存在其一；
`source_community_name` 在旧挂牌入口迁移时允许为空，后续真实采集后补齐。

建表脚本位于 `sql/property_records_schema.sql`，字段和表内注释均为中文。该模块使用独立的 `persist/property_records.sqlite3`，写入前通过 `CommunityDatabase.get_by_id()` 校验 `community_id`、城市和行政区。

## 直接写入

```python
from app.property_records import PropertyRecordsDatabase

database = PropertyRecordsDatabase()
database.upsert_deal(
    community_id=123,
    city="深圳",
    administrative_district="罗湖区",
    source_platform="lj",
    source_community_name="城市天地广场",
    deal_date="2026-06-21",
    area_sqm="88.6㎡",
    total_price="370万",
    unit_price_yuan="41761元/㎡",
)
```

成交出库时使用 `list_deals(community_id, deduplicate=True)`，按 `community_id + 成交日期 + 建筑面积 + 总价 + 单价` 严格合并跨平台相同事实，并返回来源平台列表。不完全一致的记录不会自动合并。

## RPA 入库编排

```python
from app.property_records import PropertyRecordsIngestion

ingestion = PropertyRecordsIngestion()
report = ingestion.ingest_platform_result(
    community_id=123,
    city="深圳",
    administrative_district="罗湖区",
    source_platform="链家",  # 也可传 lj
    source_community_name="城市天地广场",
    deal_page_url="https://example.com/community/deal",
    listing_page_url="https://example.com/community/listing",
    deal_records=[
        {"area": 88.6, "date": "2026.06.21", "total_price": 370, "price": 41761}
    ],
)
```

RPA 当前成交字典中的 `total_price` 按“万”解释，`price` 按元/平方米解释；也支持已经标准化的 `total_price_yuan` 和 `unit_price_yuan`。缺少日期、面积、总价或单价的成交行会跳过并记录在 `report.skipped_deals`，不会写入成交事实表。

`ingest_rpa_result()` 可直接接收 RPA 的 `PlatformResult`。它只读取真实的 `deal_records`，不会把安居客或乐有家的均价顶替值写成成交。挂牌入库需要调用方提供带 `listing_url` 的记录，因为详情 URL 是否存在取决于各平台页面适配器。

传入 `listing_page_url` 或 `deal_page_url` 时，入库层会保存或补全同一条
`community_platform_pages` 记录，不会清空另一类已确认入口。小区级入口用于后续批量采集，
单套 `listing_url` 则用于某一套房源的更新和去重。

挂牌记录更新成功后，会在同一个事务中追加一条价格日志。早于当前 `last_seen_at` 的迟到采集结果不会覆盖当前记录，也不会追加有效价格日志。前端读取同一 `listing_record_id` 的最近两条日志后自行计算总价或单价涨幅。


## 挂牌下架

单条下架：

```python
database.mark_listing_deleted("fang", listing_url)
```

批量更新时，确认本次列表页面有效并拿到至少一个 URL 后，可调用 `mark_listings_not_seen()`；本次未出现的旧记录会逻辑删除。空 URL 列表会被拒绝，避免空页误删整个小区挂牌数据。重新抓到同一 URL 时，`upsert_listing()` 会自动恢复 `is_deleted=0`。

## 边界

本模块目前只提供 Python 底层接口，不新增 FastAPI 路由，也不修改现有 RPA 采集流程。上层请求方仍需先调用 `community` 模块取得并确认 `community_id`，再将 RPA 结果交给本模块。
