# 小区主数据与房源记录（community_data / property_records）

> 一句话定位：`community_data` 管"小区是谁"（身份主数据查询），`property_records`
> 管"采到了什么、从哪采的"（挂牌/成交/平台入口存储）。两者互不依赖，由编排层用
> `community_id` 串起来。

## 1. community_data：小区主数据

- 存储：`persist/community_data.sqlite3`（独立 SQLite，与 RPA 运行时解耦）。
- 对外只暴露两个 Python 接口（包入口，非 HTTP），供编排层等调用方使用：

```python
from app.community_data import resolve_communities, find_nearby_communities
```

- `resolve_communities(city, district, name)`：按正式名 / 别名 / 期数查小区，
  只返回住宅；多期未指定期数返回空列表（调用方需指定期数重查）；精确未命中
  走"期数归一 → 简称后缀"两级兜底（兜底只影响查询，不写库）。
- `find_nearby_communities(city, district, name, limit=3, filter_by_build_year=True)`：
  附近小区。Haversine 球面距离，半径走 `.env` 的 `COMMUNITY_NEARBY_RADIUS_METERS`
  （默认 10km），默认只保留建成年份相差 ±5 年内的候选，按"距离分带 → 年份差 →
  距离"排序。

初始化与维护脚本在 `scripts/community_data/`：`initialize_database.py` 一次性导入
`xqData.json`（可选腾讯地图补坐标）、`add_alias.py` 追加别名、
`import_manual_build_year.py` 写人工建成年份、`split_phase_records.py` 拆分合并期数。
正常查询链路只读库，不创建记录、不调用地理编码。

## 2. property_records：采集结果存储

- 存储：`persist/property_records.sqlite3`，四张表：

| 表 | 内容 | 幂等键 |
|---|---|---|
| `community_platform_pages` | 平台入口白名单（挂牌/成交页 URL） | `community_id + source_platform` |
| `listing_records` | 挂牌现状快照（未再采集软删除 `is_deleted`） | `source_platform + listing_url` |
| `listing_record_logs` | 挂牌价格变动日志 | 随挂牌行追加 |
| `deal_records` | 成交事实 | 六列事实键（平台/小区/日期/面积/总价/单价） |

- 写入入口唯一：`app/property_records/ingestion.py` 的 `record_platform_result`
  （PlatformResult 全量落库 + 下架同步）。比价完成后由编排层后台调用，重复采集
  幂等，不会产生重复行。

## 3. 两个模块的交互（都经编排层，互不 import）

```text
resolve_communities ──→ 确认小区身份，得到 community_id
                                │
                                ▼
   按 community_id 查 property_records 入口表（community_platform_pages）
                                │  得到各平台挂牌/成交页 URL 白名单
                                ▼
                     RPA 按 URL 直达采集
                                │
                                ▼
   采集结果按 community_id 写回 property_records
   （挂牌明细 + 成交明细 + 入口行回写，幂等）
```

1. 编排层调 `resolve_communities` 确认小区身份，拿到 `community_id`；
2. 编排层按 `community_id` 读 property_records 的平台入口表，把 URL 白名单下发给
   RPA（没有入口的平台直接 `NO_DATA`）；
3. 采集完成后，编排层把各平台结果按 `community_id` 写回 property_records。

关键点：

- `community_data` 不知道 `property_records`，反之亦然；唯一关联是 `community_id`
  与编排层透传的城市/行政区。
- 小区身份只能来自 `community_data`（人工维护的主数据）；`property_records`
  不自行认领或创建小区。
