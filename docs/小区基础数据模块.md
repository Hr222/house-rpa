# 小区基础数据模块

## 1. 模块定位

`app/community_data/` 是 jeethink-rpa 的小区主数据模块，负责保存和查询自有小区记录，供 RPA 询价流程及其他业务代码复用。

该模块与浏览器、nodriver、平台适配器和询价任务队列解耦：

- 数据存储使用独立 SQLite 文件 `persist/community_data.sqlite3`。
- 小区首次不存在时，模块可创建记录并调用腾讯地图补充坐标。
- 正式查询只访问 SQLite，不读取原始 `xqData.json`。
- 模块目前只从 `app.community_data` 包入口公开两个 Python 接口，不新增 HTTP 路由。

## 2. 对外接口

```python
from app.community_data import find_nearby_communities, resolve_communities
```

### 2.1 查询小区

```python
resolve_communities(
    city: str,
    administrative_district: str,
    community_name: str,
) -> list[CommunityRecord]
```

行为：

1. 按城市、行政区和小区名称查询数据库。
2. `community_name` 支持正式名称、Excel `rename` 别名，以及不带期数的组名。
3. 以组名、正式名或不带期数的别名查询时，返回该组的全部期数；以带期数的正式名或别名查询时，只返回匹配期数。每个期数有独立 `community_id`，共享 `community_group_id`。
4. 查询不到时，以当前入参名称创建一条记录，并调用腾讯地图地理编码；地理编码失败不抛出到查询调用方，记录会保留并标记失败状态。

Excel 示例：

```text
name = 城市天地广场
rename = 城市天地,天地广场,城市广场
```

以上四个名称均可定位到正式记录“城市天地广场”。带期数的别名也参与期数匹配，不会因为别名带“一期”而重复建库。

### 2.2 查询附近小区

```python
find_nearby_communities(
    city: str,
    administrative_district: str,
    community_name: str,
    limit: int = 3,
    filter_by_build_year: bool = True,
) -> list[CommunityRecord]
```

`community_name` 的匹配规则与 `resolve_communities` 完全一致。

查询流程固定为：

1. 先解析中心小区，取得本次中心查询结果中的所有有效 GCJ-02 坐标。
2. 从同城且有 GCJ-02 坐标的候选记录中计算球面直线距离。
3. 只保留配置半径内的候选；半径外记录不会占用 `limit`。
4. `filter_by_build_year=True` 时，只保留与中心小区建成年份相差不超过 5 年的候选；候选缺少已确认建成年份时不参与该模式。
5. 小区组按组内最近期数的距离排序，距离相同时参考建成年份差；取前 `limit` 个小区组。
6. 返回选中小区组中仍在半径和年份条件内的期数，因此返回记录数可能大于 `limit`。

排序不是驾车距离或道路距离，而是经纬度上的 Haversine 球面距离，单位为米。所有参与计算的坐标必须是同一 `GCJ-02` 坐标系。

当 `filter_by_build_year=False` 时，不做建成年份范围筛选，但仍执行半径限制和地理距离排序；候选建成年份可以为空。

## 3. 数据模型

SQLite schema 位于 `sql/community_data_schema.sql`，主要表如下：

| 表 | 作用 |
|---|---|
| `community_groups` | 小区组主键、城市、行政区和规范化组名 |
| `communities` | 小区/期数记录、别名、建成年份、地址、坐标和地理编码状态 |

关键字段：

- `community_id`：单期记录主键。
- `community_group_id`：小区组主键；同一小区不同期数共享。
- `name`：正式展示名称。
- `aliases_json`：Excel `rename` 拆分后的别名数组。
- `phase` / `phase_key`：期数展示值和规范化键。
- `build_year`：已确认建成年份。业务上对外可用记录必须有值；待回填的历史记录暂存空值时不会进入默认年份筛选结果。
- `longitude` / `latitude`：腾讯地图返回的 GCJ-02 坐标。
- `geocode_status`：`PENDING`、`SUCCESS` 或 `FAILED`。
- `distance_meters`：仅由附近接口返回的运行时字段，不写入数据库。

## 4. 配置

附近查询半径不写在业务函数中，通过 `.env` 配置：

```dotenv
COMMUNITY_NEARBY_RADIUS_METERS=10000
```

单位为米，默认值为 10,000 米（10km）。配置只接受有限正数；`nan`、`inf`、零数和负数会回退到默认值。配置在模块加载时读取，修改后需重启进程。

腾讯地图配置：

```dotenv
TENCENT_MAP_API_KEY=...
TENCENT_MAP_API_SK=...
```

`.env` 只用于部署环境，不提交到版本库。

## 5. 数据导入与维护

原始 `xqData.json` 仅作为一次性初始化输入：

```powershell
python scripts/community_data/initialize_database.py `
  --xq-data path\to\xqData.json `
  --limit 100
```

初始化默认只写入数据库，不调用腾讯地图；确认数据后才显式补坐标：

```powershell
python scripts/community_data/initialize_database.py `
  --xq-data path\to\xqData.json `
  --geocode-limit 100
```

Excel 同步和建成年份回填脚本位于 `scripts/community_data/`。回填结果通过 `community_id` 写回 SQLite，避免以名称覆盖不同期数。

## 6. 代码边界

- `app/community_data/models.py`：数据模型和地理编码状态常量。
- `app/community_data/normalization.py`：名称规范化、别名和期数分组规则。
- `app/community_data/database.py`：SQLite 建表、幂等写入、查询和状态更新。
- `app/community_data/geocoder.py`：腾讯地图地理编码客户端。
- `app/community_data/config.py`：小区模块环境配置。
- `app/community_data/service.py`：两个接口的业务编排和距离筛选。
- `app/community_data/__init__.py`：唯一对外包入口，只导出 `resolve_communities` 和 `find_nearby_communities`。

该模块不修改 RPA 的 `core/models.py`、`algorithm.py`、`service.py`、`runtime.py` 或 HTTP API 路由；RPA 业务需要小区数据时调用本模块的两个 Python 接口。
